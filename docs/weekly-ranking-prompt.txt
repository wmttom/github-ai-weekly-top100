使用 Pro 推理模式执行每周 GitHub AI Top100 趋势榜单任务。

所有日期和文件名使用 Asia/Shanghai 时区。目标仓库为 wmttom/github-ai-weekly-top100，输出文件名为 YYYY年MM月DD日.csv，保存到仓库根目录 main 分支；同名文件已存在时更新或替换。

一、Trendshift 实时数据抓取
必须实时抓取并成功解析以下三个 Trendshift 官方当前页面：
1. 月度趋势：https://trendshift.io/monthly
2. 7 天趋势：https://trendshift.io/weekly
3. 当日趋势：https://trendshift.io/

不得继续使用带 trending-range=7 或 trending-range=1 参数的旧页面。可以使用网页访问工具或 curl。不得用历史缓存冒充实时数据，不得使用其他趋势网站替代，不得根据模型记忆推测项目。

Trendshift 失败重试策略：
- 对每一个指定 Trendshift 数据源分别执行实时抓取。
- 若出现 DNS 解析失败、连接失败、超时、HTTP 响应异常、页面无法解析或没有取得有效趋势项目，不立即结束；对该失败数据源最多执行 3 次总尝试。
- 第 1 次失败后等待至少 1 分钟再执行第 2 次；第 2 次失败后等待至少 1 分钟再执行第 3 次。
- 如果系统 DNS 解析异常，可使用 Google Public DNS over HTTPS https://dns.google/dns-query 查询 trendshift.io 的 DNS 记录，再继续访问原指定 Trendshift 数据源；使用 DoH 仅用于 DNS 解析，不得借此切换到其他趋势网站或使用历史缓存。
- 如果某个指定 Trendshift 数据源连续 3 次仍无法获得可验证的实时有效数据，立即终止整个任务；不生成 CSV，不修改 GitHub 仓库；明确返回具体失败的数据源、三次尝试结果和最终失败原因，等待下一步指示。
- 只有月榜、7 天榜和当日榜三个数据源全部取得可验证的实时有效数据后，才允许继续后续步骤。

二、上周榜单对比
读取仓库中上一周对应日期的 CSV；若不存在，读取日期早于本周的最新一份排行榜 CSV，并在运行摘要中说明回退文件。项目名称比较不区分大小写，最终项目字段使用 GitHub 当前真实 owner/repo 名称。对比上周排名变动只能填写：新上榜、上升N、下降N、持平。

三、榜单目标与排序
这是 GitHub AI 项目的本周趋势榜，不是历史累计 Stars 排名。排序依次重点参考：
1. Trendshift 7 天榜排名和本周出现次数；
2. Trendshift 当日榜排名和短期爆发；
3. Trendshift 月榜排名和持续热度；
4. 是否同时进入月榜、7 天榜和当日榜；
5. 本周相较上一周的热度变化；
6. 项目是否为近一年创建的新项目；
7. 最近 30 天的代码提交活跃度；
8. 项目所在 AI 子方向本周是否明显升温；
9. GitHub 当前 Stars、Forks 仅作为辅助信号，不得替代本周趋势信号。

四、筛选规则
仅保留真正与 AI 相关的项目，包括 AI coding/coding agent、通用 Agent 与多 Agent 编排、Agent Skills、MCP 与工具连接、Agent Memory 与上下文治理、RAG/知识库/知识图谱/文档解析、浏览器自动化和 Computer Use、AI 视频/图像/语音/多模态、本地 LLM/模型推理/AI 基础设施、AI 可观测/评测/安全/治理、金融/教育/医疗/营销/办公等垂直 AI 应用、机器人和具身智能。

必须剔除：
1. 明显非 AI 项目；
2. 纯教程、课程、学习路线和编程资料；
3. awesome list、curated list、项目导航和资源合集；
4. 纯系统工具、代理、VPN、播放器、下载器等非 AI 项目；
5. 最近 30 天没有代码提交的项目；
6. 已归档、禁用或无法正常访问的项目；
7. 重复项目、镜像仓库和无实质内容的 fork；
8. 一年以上的老项目，如果上一周没有上榜且本周没有明确 Trendshift 热度信号，则不得纳入。

如果过滤后无法获得 100 个符合规则且有真实数据支撑的项目，立即终止，不得用不合格或虚构项目补足。

五、CSV 字段与内容
CSV 字段及顺序必须严格为：排名,项目,热度分,对比上周排名变动,项目分类,项目 License,项目简介。

排名必须为 1 到 100 连续无缺失。项目使用真实 owner/repo。热度分根据本周趋势信号计算并归一化为整数，严格按热度分从高到低排序，后一名不得高于或等于前一名。项目分类使用清晰稳定的 AI 应用场景分类。License 必须通过 GitHub 仓库元数据或 LICENSE 文件核验；无法确认填写“未知 / 未声明”，不得猜测。项目简介不超过 300 字，使用清晰中文说明主要应用场景、能解决的问题和适合用途，信息密度足够，避免无差异通用套话。

六、写入前质量校验
必须验证：
1. 恰好 100 个项目；
2. 所有项目唯一；
3. 排名连续 1—100；
4. 热度分严格降序；
5. 所有项目均为真实存在的 GitHub 仓库；
6. 所有项目符合 AI 相关性要求；
7. 所有项目最近 30 天有提交；
8. 所有简介不超过 300 字；
9. CSV 可以被标准 CSV 工具正确解析；
10. 不得包含因逗号、引号或换行造成的字段错位。

七、推送 GitHub
校验通过后，将 CSV 写入 wmttom/github-ai-weekly-top100 仓库根目录 main 分支，使用当前 Asia/Shanghai 日期命名为 YYYY年MM月DD日.csv；同名文件存在时更新或替换。写入后重新读取文件，确认表头、前几名和第 100 名均存在。

八、运行摘要
任务结束后返回简洁摘要，至少包含：Trendshift 月榜、7 天榜、当日榜是否抓取成功以及发生重试时各自重试次数；使用的上周对比文件；最终保存文件名；GitHub 仓库和分支；GitHub 提交 SHA；本周主要新上榜项目；本周明显上升和下降的 AI 方向。若任务中止，明确中止原因，并确认没有生成或提交任何榜单。
